Unidad I · Tema 1.1

Servicios definidos en la capa de transporte

La capa de transporte proporciona el enlace fundamental entre el software de aplicación y la infraestructura física de la red, convirtiendo la entrega básica de host a host de la capa de red en canales lógicos directos de proceso a proceso.

1.1.1Comunicación lógica extremo a extremo: de host a proceso

Mientras que el protocolo IP en la capa de red se encarga exclusivamente de enrutar paquetes entre máquinas físicas o virtuales (comunicación host-a-host), las aplicaciones reales no interactúan directamente con computadoras completas, sino con procesos en ejecución específicos (un navegador web dialogando con un servidor HTTP, o un cliente de correo conectando a un daemon SMTP).

La capa de transporte resuelve esta necesidad implementando canales de comunicación lógica extremo a extremo. Desde la perspectiva de las aplicaciones emisora y receptora, ambas se comunican como si estuvieran conectadas por un enlace dedicado, abstrayendo por completo los enrutadores intermedios, las topologías físicas y los medios de transmisión subyacentes.

Principio de diseño

La capa de transporte opera exclusivamente en los sistemas finales (end systems). Los enrutadores de la red troncal únicamente procesan las capas de red, enlace y física, garantizando el principio de extremo a extremo (end-to-end principle) de la arquitectura de Internet.

1.1.2Multiplexación y demultiplexación mediante puertos

En cualquier sistema operativo contemporáneo coexisten decenas de procesos que utilizan simultáneamente la red a través de la misma tarjeta de interfaz de red (NIC). La capa de transporte hace esto posible mediante dos mecanismos complementarios:

  • Multiplexación en el emisor: Recolecta fragmentos de datos provenientes de distintos sockets de aplicación, añade las cabeceras de transporte con los números de puerto correspondientes y pasa los segmentos a la capa de red.
  • Demultiplexación en el receptor: Examina los campos de puerto en la cabecera del segmento entrante y entrega los datos con precisión al socket del proceso destinatario.

El puerto de red es un identificador numérico entero de 16 bits (rango de 0 a 65535) clasificado por la IANA en tres categorías fundamentales:

  • Puertos bien conocidos (Well-Known Ports, 0 al 1023): Reservados para servicios universales del sistema (ej. 80 para HTTP, 443 para HTTPS, 53 para DNS, 21 para FTP).
  • Puertos registrados (Registered Ports, 1024 al 49151): Utilizados por aplicaciones específicas de software (ej. 3306 para MySQL, 8080 para proxies o servidores de desarrollo).
  • Puertos dinámicos o efímeros (Dynamic/Private Ports, 49152 al 65535): Asignados automáticamente por el sistema operativo cliente para entablar sesiones temporales de corta duración.

Una conexión orientada a transporte queda unívocamente identificada por la tupla de 4 elementos: (Dirección IP Origen, Puerto Origen, Dirección IP Destino, Puerto Destino).

1.1.3Servicios de confiabilidad, control de flujo y control de congestión

A diferencia de la capa de red que ofrece un servicio de entrega de mejor esfuerzo (best-effort) sin garantías contra pérdida o duplicación, la capa de transporte puede ofrecer servicios avanzados de calidad y gobernanza de la transmisión:

  1. Entrega confiable y ordenada: Mediante números de secuencia (Sequence Numbers) y confirmaciones de recepción (ACKs), el transporte detecta paquetes extraviados y solicita su retransmisión adaptativa.
  2. Control de flujo (Flow Control): Impide que un emisor veloz sature el búfer de memoria de un receptor lento. Se implementa mediante el mecanismo de Ventana Deslizante (Sliding Window), donde el receptor notifica continuamente el espacio disponible en su búfer en el campo de ventana.
  3. Control de congestión (Congestion Control): Previene que la red en su conjunto entre en colapso cuando múltiples emisores inyectan más tráfico del que los enlaces y routers intermedios pueden procesar. Emplea algoritmos como Slow Start, Congestion Avoidance y Fast Recovery.
  4. Verificación de integridad: Campos de suma de comprobación (Checksum) en las cabeceras para validar que los bits no hayan sufrido corrupción electromagnética durante el tránsito.

1.1.4Modelos de servicio en Internet: TCP frente a UDP

La pila de Internet ofrece dos protocolos principales en la capa de transporte con características y compromisos de diseño opuestos:

Característica TCP (RFC 9293) UDP (RFC 768)
Orientación Orientado a conexión (Handshake de 3 vías) No orientado a conexión (Datagramas independientes)
Confiabilidad Garantizada con retransmisiones automáticas Sin garantías (pérdida o duplicación posible)
Orden de entrega Secuencial estricto y sin duplicados Sin garantía de orden de llegada
Naturaleza de datos Flujo continuo de bytes (Stream) Mensajes delimitados (Datagramas con fronteras)
Sobrecarga de cabecera Mínimo 20 bytes (hasta 60 con opciones) 8 bytes fijos
Casos de uso típicos Web (HTTP/HTTPS), SSH, Transferencia de archivos (FTP) Streaming de audio/video en vivo, DNS, juegos en red, VoIP

1.1.5La interfaz de Sockets: Punto de acceso al transporte

Para que los programadores puedan invocar los servicios de la capa de transporte sin descender al núcleo del sistema operativo, se definió la API de Sockets de Berkeley (BSD Sockets).

Un socket es un descriptor de archivo o manejador que representa el punto final de una conexión de red. Al crear un socket, la aplicación especifica el dominio de direcciones (IPv4 / IPv6) y el tipo de transporte requerido: 

// Creación de socket de flujo TCP en Java (bloqueante)
try (ServerSocket serverSocket = new ServerSocket(8080)) {
    System.out.println("Servidor a la escucha en el puerto 8080...");
    // accept() bloquea el hilo hasta que un cliente completa el handshake TCP
    Socket clientSocket = serverSocket.accept();
    System.out.println("Cliente conectado desde: " + clientSocket.getRemoteSocketAddress());
}
