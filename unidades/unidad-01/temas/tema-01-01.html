Unidad I · Tema 1.1

Fundamentos de Arquitectura de Red y Modelos en Capas

La comunicación entre sistemas heterogéneos y dispersos geográficamente solo es viable gracias a una arquitectura modular basada en capas jerárquicas, donde cada nivel resuelve un reto específico de transmisión abstrayendo la complejidad a los niveles superiores.

1.1.1¿Por qué diseñar redes mediante capas jerárquicas?

Una red informática moderna debe resolver simultáneamente problemas de naturaleza radicalmente distinta: desde modular ondas electromagnéticas en una fibra óptica o canal inalámbrico, hasta sincronizar peticiones web seguras mediante TLS y serializar objetos JSON en memoria de aplicación.

Si intentáramos programar una aplicación de chat o streaming mediante una única rutina monolítica que controlara directamente los pulsos eléctricos del cable y la retransmisión de bytes perdidos, cualquier cambio en la tarjeta de red obligaría a reescribir toda la aplicación. Por esta razón, la ingeniería de software y telecomunicaciones adopta el diseño en capas, cuyos beneficios fundamentales son:

  • Modularidad e interoperabilidad: Los desarrolladores de aplicaciones pueden programar sobre sockets de transporte sin preocuparse si el enlace físico subyacente es fibra óptica, Wi-Fi 6 o una conexión satelital.
  • Facilidad de mantenimiento y evolución: Si se actualiza el estándar de cifrado en la capa de aplicación, los routers intermedios que conmutan paquetes a nivel de red no requieren ninguna modificación.
  • Estandarización abierta: Fabricantes distintos pueden construir hardware y sistemas operativos diversos que dialogan fluidamente al compartir protocolos normalizados por organismos como la IETF y la IEEE.

Punto clave

Cada capa ofrece un conjunto definido de servicios a la capa inmediatamente superior, ocultando los detalles de implementación interna y comunicándose con su capa homóloga remota mediante un protocolo.

1.1.2El proceso de encapsulamiento y las Unidades de Datos (PDU)

Cuando un proceso emisor genera un mensaje, los datos atraviesan la pila de protocolos de arriba hacia abajo. En cada nivel, el protocolo local añade información de control denominada encabezado (header) y, en algunos casos, una cola de verificación de errores (trailer). Este fenómeno se conoce como encapsulamiento.

A cada bloque de datos resultante en un estrato específico se le denomina Unidad de Datos de Protocolo (PDU, por sus siglas en inglés):

  1. Capa de Aplicación: Genera los Datos o Mensajes brutos del usuario (ej. una solicitud HTTP GET).
  2. Capa de Transporte: Fragmenta el mensaje si es necesario y añade encabezado TCP o UDP, formando un Segmento o Datagrama.
  3. Capa de Red (Internet): Incorpora direcciones IP de origen y destino, conformando el Paquete (o Datagrama IP).
  4. Capa de Enlace de Datos: Añade direcciones físicas MAC y suma de verificación CRC, produciendo la Trama (Frame).
  5. Capa Física: Transforma la trama en una secuencia de Bits modulados sobre el medio físico.

1.1.3Comparativa arquitectónica: Modelo OSI vs. Modelo TCP/IP

En la literatura académica conviven dos modelos de referencia primordiales: el Modelo OSI de 7 capas (concebido por la ISO como marco formal teórico) y la Pila TCP/IP de 5/4 capas (el estándar de facto que gobierna la Internet operativa):

Nivel Modelo OSI (7 Capas) Pila TCP/IP de Internet Protocolos de Ejemplo
7 Capa de Aplicación Capa de Aplicación
(Agrupa funciones de presentación y sesión)		 HTTP/2, DNS, SSH, FTP, SMTP
6 Capa de Presentación TLS, JSON, ASN.1, MIME
5 Capa de Sesión RPC, Sockets de sincronización
4 Capa de Transporte Capa de Transporte TCP (confiable), UDP (datagramas)
3 Capa de Red Capa de Red (Internet) IPv4, IPv6, ICMP, OSPF, BGP
2 Capa de Enlace Capa de Enlace de Datos Ethernet (802.3), Wi-Fi (802.11), PPP
1 Capa Física Capa Física Cobre UTP, Fibra óptica, Ondas RF

Conclusión de diseño

En el desarrollo de software distribuido para Internet, la capa de aplicación asume directamente la serialización de datos (presentación) y la gestión de sesiones de usuario (sesión), simplificando la arquitectura a una pila de 5 capas lógicas.

1.1.4Direccionamiento por puertos y multiplexación

Una computadora conectada a la red posee una dirección IP que identifica unívocamente al equipo host. Sin embargo, en un mismo instante una máquina puede estar ejecutando un navegador web, un cliente de correo y un servidor de base de datos.

¿Cómo sabe la tarjeta de red a qué programa entregar cada paquete entrante? La respuesta es el puerto de red. El puerto es un número entero sin signo de 16 bits (0 al 65535) gestionado en la cabecera de transporte:

  • Puertos bien conocidos (0 a 1023): Reservados para servicios estándar del sistema (ej. 80 para HTTP, 443 para HTTPS, 53 para DNS, 22 para SSH).
  • Puertos registrados (1024 a 49151): Utilizados por aplicaciones de proveedores específicos (ej. 3306 para MySQL, 8080 para Tomcat).
  • Puertos dinámicos o efímeros (49152 a 65535): Asignados automáticamente por el sistema operativo a los clientes para una conexión temporal.

La combinación de una Dirección IP y un Puerto de Transporte define un Socket (ej. 192.168.1.15:443), permitiendo la multiplexación y demultiplexación de múltiples canales de datos sobre una única interfaz física. 

// Creación de socket de flujo TCP en Java
ServerSocket serverSocket = new ServerSocket(8080);
System.out.println("Servidor a la escucha en el puerto 8080...");
Socket clientSocket = serverSocket.accept(); // Bloquea hasta recibir una conexión
