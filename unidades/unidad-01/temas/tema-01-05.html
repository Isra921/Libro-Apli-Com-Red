Serialización

La serialización transforma el estado de estructuras de datos y objetos en memoria en una secuencia lineal de bytes homogénea, apta para ser transmitida a través del socket y reconstruida fielmente en el receptor remoto.

1.5.1Concepto de serialización y marshaling

En la memoria de una aplicación, un objeto complejo reside como una colección de punteros, referencias dispersas y bloques de datos en el montículo (heap). Como un socket de red solo puede transmitir una secuencia unidimensional continua de bytes, se requiere el proceso de serialización (marshalling) para empaquetarlo y su contraparte, la deserialización (unmarshalling), para reconstruirlo en el destino.

1.5.2Orden de bytes: Network Byte Order (Big-Endian)

Diferentes arquitecturas de procesador almacenan números enteros de múltiples bytes en órdenes opuestos:

  • Little-Endian (x86 / ARM): Almacena el byte menos significativo en la dirección de memoria más baja.
  • Big-Endian (Network Byte Order): Almacena el byte más significativo primero. Este es el estándar obligatorio en los protocolos de Internet (IETF RFCs).

En lenguajes como C, se emplean funciones de conversión como htons() (Host to Network Short) y ntohl() (Network to Host Long). En Java, los streams de red serializan por defecto en formato Big-Endian.

1.5.3Transmisión de objetos con ObjectOutputStream

Java provee el mecanismo nativo mediante la interfaz marcadora Serializable: 

// Envío de un objeto estructurado por socket
try (ObjectOutputStream oos = new ObjectOutputStream(socket.getOutputStream())) {
    MensajeRed mensaje = new MensajeRed("CHAT_MSG", "Hola mundo desde ESCOM");
    oos.writeObject(mensaje);
    oos.flush();
}
