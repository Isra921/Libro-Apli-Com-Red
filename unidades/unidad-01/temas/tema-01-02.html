Modelo cliente-servidor

El modelo cliente-servidor es el paradigma arquitectónico distribuido más extendido en Internet, caracterizado por una clara asimetría funcional donde un host pasivo ofrece servicios centralizados a múltiples clientes activos que inician las solicitudes.

1.2.1Asimetría de roles en la arquitectura de red

A diferencia de las arquitecturas entre pares (P2P) donde los nodos son simétricos, el modelo cliente-servidor se fundamenta en una separación estricta de responsabilidades:

  • Servidor (Host pasivo): Es un proceso que se ejecuta de forma continua sobre una máquina con dirección IP conocida (o accesible mediante nombre de dominio) y se coloca en un estado de espera pasiva para escuchar peticiones de conexión en un puerto determinado.
  • Cliente (Host activo): Es un proceso que inicia activamente la comunicación hacia el servidor en el momento en que requiere consumir un recurso, empleando un puerto efímero asignado dinámicamente por su sistema operativo.

Característica fundamental

Los clientes nunca se comunican directamente entre sí bajo este modelo; toda interacción, autenticación y despacho de datos es coordinada centralmente por el servidor.

1.2.2Ciclo de vida de sockets y llamadas al sistema

El establecimiento de una sesión orientada a conexión requiere una secuencia orquestada de llamadas al sistema en ambos extremos:

  1. socket(): Crea un nuevo punto final de comunicación retornando un descriptor.
  2. bind(): Asocia el socket a una dirección IP local y a un número de puerto específico (obligatorio en el servidor).
  3. listen(): Pone al socket en modo pasivo y define el tamaño de la cola de espera de conexiones pendientes (backlog).
  4. accept(): Suspende la ejecución del servidor hasta que arribe una solicitud de conexión entrante, retornando un nuevo socket dedicado para dialogar exclusivamente con dicho cliente.
  5. connect(): Ejecutada por el cliente para iniciar el apretón de manos (handshake) con la dirección y puerto del servidor.
  6. read() / write(): Intercambio bidireccional de flujos de datos.
  7. close(): Cierre ordenado de los descriptores y liberación de los buffers asociados.

1.2.3Estructura prototipo en Java

A continuación se ilustra la correspondencia entre los roles de servidor y cliente mediante la API estándar de sockets: 

// SERVIDOR: Escucha pasiva y atención
ServerSocket server = new ServerSocket(5000);
System.out.println("Servidor a la escucha...");
Socket cliente = server.accept(); // Bloquea hasta conexión

// CLIENTE: Conexión activa
Socket socket = new Socket("127.0.0.1", 5000);
System.out.println("Conexión establecida con éxito.");
