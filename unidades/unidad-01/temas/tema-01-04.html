Sockets orientados a conexión bloqueantes

En los sockets bloqueantes orientados a conexión (TCP), las operaciones de lectura, escritura y aceptación suspenden la ejecución del hilo hasta que la condición requerida se satisface o se agota el temporizador de espera.

1.4.1Comportamiento y semántica del modo bloqueante

El modo de operación por defecto al crear un socket en la mayoría de los sistemas operativos es el bloqueante (blocking mode):

  • accept(): Suspende al hilo en el kernel hasta que un cliente remoto complete el handshake TCP.
  • read() / InputStream.read(): Si el buffer de recepción TCP de la tarjeta de red está vacío, el hilo pasa a estado de espera (WAITING / BLOCKED) hasta que lleguen nuevos bytes o se cierre el canal remoto.
  • write() / OutputStream.write(): Si la ventana de congestión o el buffer de transmisión local está lleno, el hilo se bloquea hasta que el receptor confirme la recepción de datos previos liberando espacio.

1.4.2Transferencia de flujos y archivos en red

Para transmitir archivos a través de un socket bloqueante, se utilizan búferes intermedios de lectura/escritura (típicamente de 4 KB u 8 KB) para maximizar el throughput sin sobrecargar la memoria RAM: 

// Envío de archivo con socket bloqueante en Java
try (FileInputStream fis = new FileInputStream("reporte.pdf");
     OutputStream os = socket.getOutputStream()) {
    byte[] buffer = new byte[8192];
    int leidos;
    while ((leidos = fis.read(buffer)) != -1) {
        os.write(buffer, 0, leidos);
    }
    os.flush();
}

1.4.3Gestión de temporizadores y cierre ordenado

Para evitar que un hilo quede bloqueado indefinidamente ante una desconexión abrupta o partición de red, se configura el temporizador de lectura: 

socket.setSoTimeout(5000); // Lanza SocketTimeoutException tras 5 segundos de inactividad
